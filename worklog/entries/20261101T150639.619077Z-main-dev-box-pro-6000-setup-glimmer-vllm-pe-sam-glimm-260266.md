# Dev box PRO 6000 setup: Glimmer vLLM, PE, SAM, Glimmer-DE read

## Summary

The `dev` box (4x RTX PRO 6000 Blackwell, 96 GB each; 219 GB RAM) is now set up as the fast model-serving machine, after the gfx1151 box went offline with no physical access available. Glimmer (the lead's `shisa-ai/Muse-Glimmer-30B-FP8-BLOCK` download) serves under vLLM 0.30.0 on GPU 0, AnyJev 0.3.0 is installed, and PE-Core-L14-336 plus SAM 3.1 are staged and smoke-tested on the CUDA stack. The headline measurement: a no-training Glimmer-DE restricted read that cost 2.69 s/photo on the zbook llama.cpp server costs **0.2-0.5 s cold and 0.03 s per additional rotation** under vLLM, because prefix caching reuses the image KV across questions — AnyJev's L0 rotation averaging, unaffordable on llama.cpp, is effectively free here. The working scaffold differs from llama.cpp's: prefill `Category:` plus an explicit no-markdown instruction (mass 0.46-0.64; the model's first instinct is a markdown-bold answer, which shifts the boundary by one token — recorded so nobody re-derives it). Disk is the standing constraint on dev: 25 GB free on a 3.7 TB volume at measurement time.

## Changes

- On `dev` only (not repo state): `~/models/PE-Core-L14-336` (2.6 GB), `~/models/sam3.1-unsloth` (4.5 GB incl. quants; bf16 is the used artifact), `perception_models` cloned to `/tmp`, `timm`/`einops`/`ftfy` and `anyjev` pip-installed into the `vllm` env (with PIP_REQUIRE_HASHES=0; the box's pip requires hashes by default).
- vLLM server left running on dev GPU 0: `vllm serve shisa-ai/Muse-Glimmer-30B-FP8-BLOCK --port 8000 --max-model-len 8192` (model load 32.57 GiB). Glimmer-DE probe scripts in `/tmp` on dev (`gde_dev_test.py`, `gde_dev_variants.py`, `gde_dev_rot.py`).
- `MODELS.md`: hardware note gains the dev box and its serving role.

## Validation

- SAM 3.1 on PRO 6000: loads in 1.7 s, `dish` prompt returns 12 masks (top scores 0.63-0.66) on a sample food photo, 2.11 GB peak.
- PE-Core-L14-336 on PRO 6000: food photo scores food 0.873 (correct top), 2.75 GB peak.
- Glimmer-DE read, variant A scaffold (`Category:` prefill, no-markdown instruction): both pilot photos correct (food 0.96 mass-normalized, sightseeing 0.73); masses 0.621/0.469.
- Five rotations of one food photo: 0.05 s then 0.03 s each, food probability 0.94-0.99 in every rotation, mass 0.46-0.64 — prefix cache reuse and low position bias on this item.
- Comparative rates for context: llama.cpp zbook Glimmer-DE raw read 2.69 s (640 px) / 6.4 s (1024 px); generative Glimmer triage 19.4 s/photo.
