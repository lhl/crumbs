# Glimmer vision runs on Strix Halo via llama.cpp HIP (GLM-05 first pass)

## Summary

GLM-05 first arm measured: Muse Glimmer does image processing on the Strix Halo box (`zbook`, Radeon 8060S / gfx1151, 125 GB unified memory) via mainline llama.cpp HIP. Mainline llama.cpp carries full Glimmer support — `muse-glimmer` arch, mtmd vision graph (incl. its sparse/patch-temporal variants), HF→GGUF conversion — so no fork was needed. Artifacts (official `meta-models/Muse-Glimmer-30B-GGUF`): Q4_K_M 16.76 GB + mmproj vision tower 1.40 GB + dflash draft 1.63 GB. Glimmer has no integrated MTP head; its speculative companion is the DFlash draft model, and llama.cpp's `--spec-type draft-dflash` drives it (measured acceptance 46–76%). Vision verified three ways: llama-mtmd-cli and llama-server (both need `--jinja` for Glimmer's chat template; without it mtmd-cli crashes in template application), exact transcription of a synthetic menu card, and sensible descriptions of two sampled real photos. Headline numbers (single requests, full-res photos): image+prompt processing ≈ 4,150 prompt tokens at ~88 tok/s (~47 s prefill for a full-res photo — image-token-bound, so downscaling before extraction is the obvious tuning knob), generation 17–27 tok/s with dflash on. That makes the consumer-hardware story real but throughput-limited: extraction at full resolution is roughly a photo a minute, fine for background organizing, not for interactive bulk import. This does not close GLM-05's acceptance (no 500-photo batch, no BF16 comparison possible on this box) and says nothing about the PRO 6000 primary arm (GLM-01/02), which remains unmeasured.
