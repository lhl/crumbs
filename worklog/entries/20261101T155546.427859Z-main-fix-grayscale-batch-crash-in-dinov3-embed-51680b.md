# Fix grayscale batch crash in DINOv3 embed

## Summary

The full-corpus DINOv3 embed stopped at 5,848 of 9,669 embeddings: grayscale-source photos in the 2025/2026 set produce 1-channel tensors after the DINO processor, and stacking a batch that mixes them with RGB tensors raises `RuntimeError: stack expects each tensor to be equal size`. The 2019 sample was all-color, so the bug survived until the big import. Embed now converts every analysis image to RGB on load — the standard input contract for the model — and the pass was restarted (it skips already-embedded photos, so the 5,848 completed rows are kept).

## Changes

- `crumbs/embed.py`: `.convert("RGB")` on analysis images in `embed_all`, with the failure mode recorded in a comment.

## Validation

- Reproduced from the crashed run's traceback in the embed log (batch entry 10 is the 1-channel tensor).
- `python3 -m py_compile crumbs/embed.py` passes; embed restarted against the corpus (completion count reported with the full-corpus processing record).

## Next

- None for embed; the same convert-on-load contract already holds in the SAM/PE runners, which were checked when this was found.
