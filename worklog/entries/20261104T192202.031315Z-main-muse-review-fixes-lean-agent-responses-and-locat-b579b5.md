# Muse review fixes: lean agent responses and location age

## Summary

The Muse agent reviewed `docs/muse/` (worklog 20261104T191427) and asked for two server tweaks and a docs correction:
- **Lean agent responses:** with the agent token, `/v1/ask` now drops the tool trace (replaced by a `lookups` count) and caps `results` at 10. That keeps the remote agent's context small; the owner token still gets the full response.
- **Location age:** responses that use `near=current` (`/v1/ask`, `/v1/nearby`) now include `current_location {as_of, age_s}`, so stale or missing phone locations can be flagged instead of silently used.
- **Docs:** Muse never holds the raw token (a credential helper substitutes it per registered host). The base URL is plain configuration, and one MagicDNS address form should be used everywhere.

## Changes

- `crumbs/api.py`: `_for_agent()`, `_location_age()`, and `AGENT_MAX_RESULTS = 10`. The ask route builds the response once, then applies the agent trimming.
- `tests/test_api.py`: with a patched agent returning 15 results and a 2-step trace, the agent token gets 10 results with no trace (`lookups: 1`) plus a null location age, and the owner token gets all 15 and the trace.
- `docs/muse/crumbs-skill.md` and `docs/muse/SETUP.md`: credential-helper model, MagicDNS address, response shape, staleness rule, the spike check, and running a token-free localhost server alongside the tailnet one.
