# Make location import idempotent (export-merge dedupe)

## Summary

Reviewing the Muse-produced `wanderings-sync` tooling surfaced a real defect in our importer: re-importing an overlapping Wanderings export would duplicate every shared point, because `location_records` had no dedupe. Adopted the same merge key that tool uses (timestamp + coordinates): the importer now inserts with OR IGNORE under a unique (ts_ms, lat, lon) index and reports how many points were actually new. The sync daemon itself was assessed as a useful but unfinished local-only skeleton (it automates the wanderin.gs Export click from the user's own signed-in browser profile; its selectors/sync-signal are unverified TODOs) and kept out of this repo — it is Muse-platform tooling for the owner's machine, not Crumbs product code.

## Changes

- `crumbs/db.py`: unique index `idx_loc_dedupe` on `location_records(ts_ms, lat, lon)`.
- `crumbs/locations.py`: import uses INSERT OR IGNORE and returns `points_in_file` / `new_points`.

## Validation

- Re-import of the current 25,165-point export after the change: `{'points_in_file': 25165, 'new_points': 0}` and the table count is unchanged; the unique index built cleanly over existing rows (proving no dupes were present).

## Next

- The sync loop, when the owner finishes the daemon's discovery step: daemon export → `crumbs import-locations` (now safe to repeat) → `stays`/`tz`/`correlate` re-runs. Nothing about that loop requires the Muse-side ingest file; our importer subsumes it.
