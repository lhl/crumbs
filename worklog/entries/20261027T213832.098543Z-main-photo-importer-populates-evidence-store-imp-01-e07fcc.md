# Photo importer populates evidence store (IMP-01)

## Summary

IMP-01 working end-to-end on the DAT-01 sample: `crumbs import-photos data/sample-2019` scanned 440 photos, inserted 440 media_items (0 duplicates, 0 failures), reconciling exactly with the sampler manifest (413 with EXIF datetime, 399 with GPS). Each item stores content-hash (sha256, UNIQUE — re-import dedupes by construction), source path (originals untouched), normalized ISO camera-local datetime with its source marked, GPS, camera model, and dimensions; every photo also got a 1024px analysis JPEG (66 MB total) that downstream model stages read, so models never touch HEIC or full-res originals. EXIF datetime format mixing (`2019:01:02` vs ISO) is normalized at import. Still owed within IMP-01's acceptance: HEIC is handled via ImageMagick (recorded, works), corrupt-file handling is a warned skip in analysis rendering only, and IMP-03 timezone inference is a separate unit — times are camera-local until then.

## Changes

- `crumbs/exif.py`: batch exiftool JSON reader (datetime/GPS/model/dimensions/offset).
- `crumbs/importer.py`: tree scan (HEIC/JPG/PNG), sha256 dedupe, media_items insert with `provenance='observed'`, ImageMagick analysis-image rendering (1024px, auto-orient, q85), datetime normalization.
- `crumbs/cli.py`: `init-db`, `import-photos`, `stats` subcommands. Local state only (not committed): `data/crumbs/crumbs.db` + `data/crumbs/analysis/*.jpg` (ignored).
