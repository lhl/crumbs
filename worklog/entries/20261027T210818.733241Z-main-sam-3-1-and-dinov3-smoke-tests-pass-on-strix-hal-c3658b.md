# SAM 3.1 and DINOv3 smoke tests pass on Strix Halo

## Summary

Both remaining local vision stacks now run on the Strix Halo box (zbook, Radeon 8060S, torch 2.13.0+rocm10.0.0, transformers 5.15.0). SAM 3.1 (bf16, 840M params, `unsloth/sam3.1` transformers checkpoint; official `facebook/sam3.1` is the license/source reference and the lead's gated access is granted): text-prompted segmentation verified end-to-end on a sampled real photo — first prompt 2.55 s warmup-inclusive, ~0.48 s per subsequent prompt at full photo resolution; the 'bridge' mask was visually confirmed to cover exactly the bridge deck (score 0.82, 9.4% coverage), with sensible river/snow masks. The unsloth FP8 checkpoint is **not** a drop-in quant: it stores torchao tensors with no quantization config, so a plain load silently re-initializes the quantized layers — recorded so nobody 'benchmarks' a corrupted model; bf16 (~0.5 s/prompt) is the E4 path. DINOv3: model selection recorded (ViT-B/16, ViT-S/16, ConvNeXt-Small for the E1 bake-off; ViT-L/16 ceiling-only; all LVD-1689M). Official `facebook/dinov3-*` repos are manual-gated and the lead's approval is pending, so the smoke used the camenduru ViT-L/16 mirror (card claims byte-identical safetensors): transformers `DINOv3ViTModel` embedded test photos at ~200 img/s fp32 with sane similarity behavior. The zeromodels collection mirrors turned out to be Keras `.h5` weights and were not used. Upstream `facebookresearch/sam3` and `facebookresearch/dinov3` are cloned on zbook for reference implementations.

## Validation

- SAM: `Sam3Model`/`Sam3Processor` bf16 on gfx1151; prompts bridge/river/snow returned masks (1/1/27) with top scores 0.82/0.64/0.75; bridge mask overlay rendered and inspected — the mask is the bridge deck at the frame's top, matching what Glimmer described in the same photo.
- SAM FP8: load report showed `_weight_qdata`/`_weight_scale` UNEXPECTED and corresponding `weight` MISSING (randomly re-initialized) under a plain load, proving the file needs explicit torchao wiring.
- DINOv3: `DINOv3ViTModel` (303M) loads; single/batch forwards ~5 ms/img at processor-default resolution (~200 img/s); identical-photo cosine 1.0 vs 0.92 for a different photo (CLS cosine baseline is high; directionally sane for a smoke test, not an E1 result).
- Official DINOv3 download attempt returned the expected gated-access error, confirming the approval is still pending.
