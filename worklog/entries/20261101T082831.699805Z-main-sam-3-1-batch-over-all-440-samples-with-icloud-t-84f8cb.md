# SAM 3.1 batch over all 440 samples with iCloud timing

## Summary

SAM 3.1 (bf16, strixhalo/gfx1151, `therock` env) has now run over the full initial sample: 440/440 analysis images, 0 failures, with five evidence prompts (sign, menu, receipt, dish, storefront) per photo at threshold 0.5. Measured cost is 2.83 s/photo mean (median 2.81, p90 2.86) for all five prompts — about 0.57 s per prompt including image re-encoding per prompt — with 4.17 GB peak unified allocation. Extrapolated to the iCloud set (9,199 images at the same 1024 px analysis size), a full SAM pass is ~7.2 hours of strixhalo time, running in parallel with Glimmer on zbook; for comparison, Glimmer triage alone extrapolates to ~49 hours for the same set, so SAM adds roughly 15% if run on everything, and proportionally less if run selectively after classification. This is a throughput/coverage measurement, not EXT-04: whether SAM crops improve Glimmer extraction is still unmeasured.

## Validation

- Run log: 437 images in 1233 s wall after a 3-image test batch; combined recorded total 1247 s over 440 rows, 0 error rows in `results.jsonl`.
- Prompt hit rates over 440: sign 168 (38.2%, top-score median 0.848), dish 41 (9.3%, 0.871), storefront 38 (8.6%, 0.637), menu 26 (5.9%, 0.750), receipt 8 (1.8%, 0.707); at least one prompt hit on 208 photos (47.3%).
- Extrapolation computed from the measured mean: 9,199 x 2.83 s = 7.2 h; evidence-share equivalent (47.3%) = 3.4 h. Assumes iCloud photos go through the same 1024 px analysis rendering (IMP-01) first, which the pipeline already does.
