# Place registry and candidate triangulation v1 (REC-07)

## Summary

REC-07 v1 built and populated: a locally cached restaurant/place registry (1,618 unique named places) with distance-ranked candidates for every food-bearing visit (2,121 candidates over 58 visits; 53 visits have at least one candidate, 5 have none — sparse-OSM areas, recorded as honest unknowns). Candidates are `gps`-evidence only and nothing is auto-confirmed, per the triangulation rules. The registry is searchable two ways from the CLI — `place-search <name>` and `nearby --lat/--lon --radius [--kind]` — which is the substrate the anchor-recommendation flow needs. Demonstrated on the corpus's Kyoto-area visit: top candidates are the neighborhood's actual tofu/Japanese restaurants at 87–285 m, and a 500 m `nearby` search around an anchor place returns the same cluster ranked by distance. Dev lookup is Overpass (OSM) with mirror rotation + retries after real 504s; each area is cached in SQLite so it is fetched once. This remains a dev-stage source: it reveals queried visit centroids to the Overpass operator, and the shipped path is PMTiles-POI ingestion from locally held extracts — the schema already carries `source` so both coexist and provenance stays visible.

## Changes

- `crumbs/db.py`: `places` (external_id, name, kind, cuisine, lat/lon, source, provenance) and `visit_place_candidates` (visit, place, distance_m, evidence, score, status, created_by) tables.
- `crumbs/places.py`: Overpass amenity query (nodes+ways, name-required, 3-mirror rotation with backoff after 504s), upsert + candidate insert with `1/(1+d/100)` score, food-visit selection from classifications, resume-skips, per-visit failure tolerance; `nearby()` and `search_name()`.
- `crumbs/cli.py`: `places-fetch [--radius]`, `nearby`, `place-search` subcommands.

## Validation

- Fetch totals across two runs (first died on Overpass 504s after 6 visits; second rotated mirrors): 58 visits queried, 0 failed, `places-fetch: {'visits_queried': 52, 'places_seen': 1885, 'candidates': 1885, 'visits_with_candidates': 47, 'skipped_done': 6, 'failed': 0}`; DB counts places 1,618 / candidates 2,121.
- Anchor demo executed: Kyoto visit's top-8 candidates are plausible named restaurants/cafes 87–285 m away; `nearby` (500 m) around an anchor restaurant returns the same cluster distance-ranked; a Tokyo food visit's nearest candidate is 26 m. Dense areas truncate at the 60-result Overpass page size (recorded as a known v1 limit).
