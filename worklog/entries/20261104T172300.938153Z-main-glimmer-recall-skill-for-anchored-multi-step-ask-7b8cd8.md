# Glimmer recall skill for anchored multi-step Ask

## Summary

The demo's headline question was an anchored, multi-step recall question. The Glimmer agent could not answer it. The agent had only single-lookup tools, and its final answer-only turn returned HTTP 500 from llama.cpp ("does not match the expected peg-native format"): under `tool_choice: none`, Glimmer still tried a tool call and the parser rejected it. The original question also concerned a 2023 meal whose photos are not in the store yet, so the lead switched the demo to a 2025 question that the store can answer.

This unit adds a recall skill and three tools:
- The skill (`crumbs/skills/recall.md`, appended to the system prompt) classifies the question into dish, city, named place, near me, or anchored recall.
- For anchored recall the agent works in three steps. `find_photos` locates the anchor in photo text. `day_timeline` splits that day into moments (runs of photos with no gap over 20 min). The name is then read from photo text in the matching meal moment.
- `look_at_photos` sends one local preview to the same local Glimmer, only for photos a tool already returned, and labels the output as a model observation.

Grounding and the 500 fix:
- Moments are cited as `[p<photo id>]` and grounded like visits: citations of photos no tool returned are removed.
- A photo-text name is never promoted to a verified place, so moment cards have no place.
- Answer-only turns now send no tools at all, which fixes the 500.
- Rounds raised from 3 to 5.

## Changes

- `crumbs/moments.py` (new): `visit_moments`, `moment_line`, punctuation-insensitive `find_photos`, `day_visits`, and `moment_card`.
- `crumbs/skills/recall.md` (new) and `pyproject.toml` package-data so the skill ships with the package.
- `crumbs/agent.py`:
  - new tools and the `[p]` citation grounding;
  - meal moment cards ordered first;
  - a `look` trace step;
  - an answer-only turn with no tools;
  - `MAX_ROUNDS` 5;
  - an injectable `vision` hook for tests.
- `spike/map-globe/src/main.js`: cards show the moment time and up to two photo-text names; the answer strips `[p]` as well as `[v]` citations.
- `tests/test_agent.py`:
  - a synthetic day fixture;
  - an anchor → timeline → moment-card test, including removal of an invented `[p]` citation;
  - a test that look_at_photos refuses photos no tool returned;
  - an assertion that answer-only turns offer no tools.
- `MODELS.md` and `IMPLEMENTATION.md`: agent notes updated. "Never sees photos" is now scoped to say it sees a photo only through look_at_photos.

## Validation

- `python3 -m unittest discover -s tests`: 36 passed.
- Live through the zbook tunnel (Q4_K_M `llama-server`), on the real store; the values stay in local notes because the repo is public:
  - The demo anchored question gave the same answer on three runs: find_photos then day_timeline, 2 tool calls, 32.8 s, 32.3 s, and 28.2 s through the PWA. The answer named the photo-text sign of the lunch moment and cited 2 moments, with 0 unsupported citations.
  - A shaved-ice variant answered correctly in 61 s with 3 calls.
  - A soup-dumpling regression query: 1 call, 17.1 s.
- Before the nudge in the skill and the timeline note, the same question took 4 calls and 55–68 s, and one earlier run failed with the 500 described above.
- PWA (headless Chromium, `crumbs serve` plus Vite, read-only query): answer text without citations, trace "2 lookups · 28.2s", 2 cards, 5 thumbnails loaded, 0 console errors.
