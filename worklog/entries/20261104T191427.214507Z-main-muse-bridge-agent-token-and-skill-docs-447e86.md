# Muse bridge agent token and skill docs

## Summary

The lead asked whether Crumbs has Muse integration and what docs to give the Muse agent. Before this unit only the local half existed (`crumbs serve`, worklog 20261028T052535), with two gaps for an external agent. First, the caller chose the privacy tier: anyone holding the token could request `tier=2` and receive exact coordinates and file paths, although PLAN §8 says the token scope sets the tier. Second, the single token also allowed writes.

`CRUMBS_AGENT_TOKEN` is now a second bearer token for the Muse agent. It is read-only (POSTs return 403) and capped at tier 1. The Muse-side skill (`docs/muse/crumbs-skill.md`) and the owner setup steps (`docs/muse/SETUP.md`) describe the endpoints and rules as built. The skill covers:
- health first;
- the 30–90 s `agent=1` timing;
- keeping provenance words;
- unknown stays unknown;
- no coordinates;
- no writes.

## Changes

- `crumbs/api.py`: `_role()` returns owner, agent, or unauthorized. The agent role caps the tier at 1 and is refused on POST. Behaviour with no tokens configured (localhost dev) is unchanged.
- `tests/test_api.py`: a synthetic photo row checks that the owner token at tier 2 gets the exact coordinate and file path, while the agent token gets the rounded coordinate and no path. It also checks that agent POSTs to review and current return 403.
- `docs/muse/crumbs-skill.md` (new) and `docs/muse/SETUP.md` (new). Neither contains a token value, IP address, or personal data.
- `IMPLEMENTATION.md`: API-09 note.
