# Label taxonomy v2: other for humans, evidence as its own axis

## Summary

Label taxonomy v2, decided with the lead during the first labeling session (the 7 trial labels were reset to zero at the lead's request, locally only). Two fixes from live use: (1) menu and receipt now have a first-class place in labeling — as **evidence labels**, not categories, because category is the scene axis and evidence is the content axis (DAT-03's original design): a menu photo is category food + evidence menu, and making menu a category would collide with dish photos that also contain menus and break comparability with the 440 stored model classifications; (2) humans label **other** instead of unknown — the labeler knows what the photo is, it just fits no category (a tchotchke, a screenshot, a pet); **unknown stays the model's abstention word** and scoring already treats a model unknown against any human label as an abstention. `personal` is defined in the UI as everyday life at home/locally (people, home, everyday objects and restaurants) — not 'private'. A tchotchke at a restaurant: trip if traveling, personal if local, + interior evidence. Evidence labels are extensible: the UI has a free-text field to create new ones as labeling surfaces new cases, so the taxonomy grows from use instead of being fixed up front (EMB-07's revision loop, applied at label time).

## Changes

- `crumbs/label_server.py`: category buttons are now sightseeing/trip/personal/food/other with plain definitions and worked examples in the page; evidence multi-select chips (dish, menu, receipt, sign, storefront, interior, lodging, landmark, people, nature, document, other) prefilled from the model's suggestions; free-text new-evidence field; POST stores `field='evidence'` label rows. A model 'unknown' pre-selects 'other' for the human.
- `crumbs/score.py`: taxonomy v2 documented; latest label pass wins per photo (a re-label's category replaces, and dish/evidence sets reset with it); new `evidence` section scoring user evidence sets against model evidence types (micro precision/recall + per-label tp/fp/fn).

## Validation

- Throwaway DB restart of the labeler (port 18767): page renders the new taxonomy; POST with category sightseeing + evidence [sign, landmark] stored correctly; `crumbs score` returned category accuracy 1.0 on the single item and evidence precision/recall 0.5 with per-label sign=tp, landmark=fn, other=fp against the model's stored evidence — the expected arithmetic for that fixture.
- Real corpus DB verified untouched by tests and reset to 0 labels at the lead's request before relaunch; the phone label server was restarted with the new code on 0.0.0.0:8765.
