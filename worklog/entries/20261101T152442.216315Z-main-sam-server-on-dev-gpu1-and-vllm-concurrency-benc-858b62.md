# SAM server on dev GPU1 and vLLM concurrency benchmark

## Summary

Two infrastructure results for the full-corpus processing. (1) SAM 3.1 now runs as a small HTTP server on dev's GPU 1 (bf16 model resident; POST image + prompt list, returns mask stats and best-mask PNGs), reached from strixhalo through an SSH tunnel because dev's firewall allows only port 22 — no firewall rules were changed. Steady-state cost is ~0.3 s/photo for the 5 evidence prompts including image transfer, against 2.83 s/photo for the same pass on strixhalo, so the corpus SAM pass moved to dev (the just-started strixhalo run was stopped; both runners are resumable and share the results format). (2) Glimmer-DE read throughput against the dev vLLM server is **flat in client concurrency**: 5.0-5.4 requests/s (0.19 s/photo) at every level from c=1 to c=64, each level on a disjoint 64-photo set so prefix caching could not flatter later levels. The bottleneck is per-request vision encoding, not client parallelism or LLM prefill batching; scaling reads means more vLLM replicas across the 4 GPUs or smaller images, not more client threads. Also closed here: PE-L finished the full corpus on strixhalo (9,237 new photos in 1075 s, 0.116 s/photo; distribution over all 9,677: unknown 4445, trip 2740, food 1168, sightseeing 779, personal 545).
