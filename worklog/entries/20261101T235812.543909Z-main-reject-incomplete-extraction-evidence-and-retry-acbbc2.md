# Reject incomplete extraction evidence and retry bounded reads

## Summary

The restarted selective pass exposed text-heavy photos whose model output exhausted the token budget inside `visible_text`. Extraction now rejects incomplete or malformed evidence and allows one larger-budget retry. Unlike the category-only benchmark's prefix recovery, an unfinished extraction is never promoted to place/dish evidence.

## Changes

- Validate required fields, text/boolean types, candidate arrays, string names, and the allowed evidence-basis values before storing a response.
- Reject an explicit output-length stop. Retry malformed/truncated responses once at 4,096 output tokens and temperature 0.2 instead of the ordinary 1,100-token, temperature-0.8 request. Persistent errors remain failures, not unknown or successful extractions.
- Three additional synthetic tests cover length-stop retry, two-attempt exhaustion, and invalid field/basis types. No dependency was added.

## Validation

- `python3 -m unittest discover -s tests -v`: nine tests passed, including HTTP/CLI partial-failure and resume checks from the preceding unit.
- `python3 -m py_compile crumbs/extract.py` and `git diff --check`: passed.
- A text-heavy image which failed the dev-local 640 px first pass was read successfully through the configured real vLLM endpoint from the 1024 px analysis copy: all required fields, 505 visible-text characters, 20.26 seconds. This verifies a real complete read, not that the automatic second attempt was needed on that call; resolution and sampling differ. Retry scheduling itself is deterministically tested against controlled responses.
- The four dev-local extraction shards are still running the preceding committed client. Once they finish, remaining failures will be resumed using this version. Aggregate completion/field validation belongs in the closing corpus entry.
