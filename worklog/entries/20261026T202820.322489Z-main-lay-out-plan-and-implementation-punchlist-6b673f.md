# Lay out PLAN and IMPLEMENTATION punchlist

## Summary

Created PLAN.md (full-spike product/engineering plan) and IMPLEMENTATION.md (exhaustive agent-handoff punchlist) from BRAINSTORMING.md, DISCOVERY.md, the rubric in README.md, and the lead's directions. PLAN covers: principles (local-only, provenance/uncertainty, no place-from-food-alone, corrections, measured claims, repo safety); scope tiers (Must vertical slice, Should, Stretch, Out); seven prioritized use cases; a three-plane local architecture (PWA / local service / local model servers) with provisional stack choices marked verify; a conceptual data model for sources, media, classifications, embeddings, extractions, places, visits, trips, dishes, corrections, agent questions, taste signals, and jobs; the seven-stage background pipeline; channels (PWA primary, voice interface, optional Muse channel in both readings — Muse Code as the build channel and an MCP-style local query interface as a product stretch — plus share export); eleven PWA flows including map, globe, and timeline; a 3-minute demo script and judging/bonus alignment; a 14-item research dependency register (R1–R14) tying every open DISCOVERY question to what it blocks, its fallback, and a decision date; a day-by-day schedule to the Nov 4 9:00 PM ET deadline with a Nov 2 feature freeze; four agent workstreams; and top risks. IMPLEMENTATION.md turns that into ~90 checkbox tasks across 14 epics (INF, DAT, IMP, STO, EMB, GLM, GDE, EXT, REC, AGT, VOI, API, PWA, QA, DEM), each with priority, acceptance criteria, and dependencies, plus a suggested day-by-day agent sequencing.

## Changes

- Added `PLAN.md` and `IMPLEMENTATION.md` as described in the summary. No implementation exists yet; acceptance criteria are written to be checkable when it does.
