# Offline geolocation context in the labeling UI

## Summary

Each photo in the labeling UI now shows where it was taken, at the lead's request: nearest city, region, and country from its EXIF GPS, plus the nearest place in the local places cache with distance. All of it is computed offline — the city/country lookup uses the `reverse-geocoder` package's bundled GeoNames data on the local machine, because sending the owner's photo coordinates to a network geocoder would leak exactly the location history this project keeps local. GPS coverage in the sample is 399/440; photos without GPS show 'no GPS for this photo'. The label server was restarted with the change; labeling progress was preserved.

## Changes

- `crumbs/label_server.py`: `geolocate()` (cached by rounded coordinates) returns lat/lon, city/region/country (small built-in country-code name map, code shown when unmapped), and nearest cached place within 50 km via the existing haversine helper. Items from `/api/next` and `/api/item/<id>` gain a `location` field; the page renders a `📍` line marked 'offline approx.'
- Local env only (not repo state): `pip install reverse-geocoder` in the base mamba env on strixhalo. The import is optional in code — without the package the UI degrades to coordinates + nearest place, never to a network call.

## Validation

- `python3 -m py_compile crumbs/label_server.py` passes.
- Throwaway DB (port 18770), items checked by media id: Tokyo coords → Tokyo, Tokyo, Japan with nearest place 26 m; Gunma coords → Numata, Gunma, Japan; Taiwan coords → Keelung, Taiwan, Taiwan. `/api/next` carries the same location field. Direct package check on Tokyo/Taipei/New York coordinates returned the expected cities offline.
