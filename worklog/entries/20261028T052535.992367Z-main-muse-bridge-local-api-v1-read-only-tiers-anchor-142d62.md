# Muse bridge local API v1 (read-only, tiers, anchor query)

## Summary

The local side of the lead's Muse bridge is implemented: `crumbs serve` is a read-only JSON API over the evidence store (stdlib HTTP, localhost default, optional Bearer token via `CRUMBS_API_TOKEN`) with `GET /v1/health` (unauthenticated), `/v1/search` (text/category over photos + extraction text), `/v1/visits`, `/v1/visit/<id>` (photos, place candidates, stay matches), `/v1/places` (name search), `/v1/nearby` (radius search incl. `near=current`), `/v1/anchor` (the demo query: anchor place + radius + date window → the window's visits near the anchor with their candidate restaurants), and token-gated `POST /v1/current` by which the owner's device sets the current location that `near=current` resolves server-side — the bridge's key privacy property, so a Muse VM can ask situated questions ('what did I have last time I was here?') without ever receiving raw coordinates from the agent side. Privacy tiers are enforced in the API (0 = counts only, 1 = redacted default with ~1 km coordinate rounding and no file paths, 2 = full), not delegated to the caller. Exercised live: health counts, 401 without token, anchor query resolving 'Sagana' to the Arashiyama visit with its ranked candidates, `near=current` round-trip, tier-0 search returning counts only. PLAN §8 now carries the full bridge design (tunnel ACL, vault-held token, persisted Muse-side skill, failure honesty); tunnel setup and the Muse-side skill are owner/platform steps, deliberately not built here. This is the local half of API-01/API-09, not their completion: the PWA-facing write/correction APIs do not exist yet.

## Changes

- `crumbs/api.py`: read-only API (endpoints above), tier rounding/stripping, current-location state, token check.
- `crumbs/cli.py`: `serve [--host] [--port]` subcommand.
- `PLAN.md` §8: Muse channel rewritten as the concrete bridge design from the lead's sketch.

## Validation

- Live curl suite against the real store with a test token: health `{media_items: 440, classifications: 440, visits: 228, places: 1618, stays: 554}`; search without token → 401; `/v1/anchor?name=Sagana&from=2019-10-01&to=2019-10-31` returned the 2019-10-09 visit 189 m from the anchor with its candidate list; POST `/v1/current` then `near=current` returned the anchor place itself at 5.1 m; tier-0 food search returned `{count: 62}` with no records (after fixing a limit/cap bug found by this test).
