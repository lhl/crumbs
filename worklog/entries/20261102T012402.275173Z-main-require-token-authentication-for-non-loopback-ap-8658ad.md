# Require token authentication for non-loopback API binds

## Summary

Non-loopback API binds now require a nonblank `CRUMBS_API_TOKEN`; localhost remains the default. This closes the API-08 access-control gap before remote Ask/voice work. Real HTTP tests exercise both authentication and browser preflight against an empty synthetic store, including a wildcard bind. No existing user server was restarted or exposed.

## Changes

- Reject an unauthenticated non-loopback bind before opening the evidence database. The CLI checks this path before its own database setup and reports a normal argument error rather than a traceback.
- Freeze the configured token when creating the handler and compare bearer credentials with `hmac.compare_digest`. Later environment changes cannot silently disable authentication on that handler.
- Add OPTIONS responses allowing Authorization/Content-Type preflight; the subsequent actual request still requires authentication. `/v1/health` remains intentionally exempt as documented.
- Close server/database resources when serving exits; update CLI help and the API module's access-boundary description.
- Add six synthetic API tests without new dependencies. The wildcard-bind test uses an empty temporary database and a clearly synthetic credential, never the owner's evidence store.

## Validation

- `python3 -m unittest discover -s tests -v`: seventeen tests passed. New tests cover blank/missing-token rejection for wildcard/non-loopback hosts, retained localhost defaults, immutable handler authentication, browser preflight, CLI rejection before creating a database, and actual authenticated/unauthenticated HTTP requests against a wildcard-bound server.
- The real HTTP tests use the actual `api.serve` function: missing/wrong credentials return 401, a valid bearer token returns the empty fixture results, and public health remains available. The CLI unsafe-bind test exits two with the token requirement and no traceback.
- `python3 -m py_compile crumbs/api.py crumbs/cli.py`, `python3 -m crumbs.cli serve --help`, and `git diff --check`: passed.
- No model server was launched and no real personal data or secret was added. A bearer token does not encrypt HTTP; remote use still belongs on a trusted LAN or authenticated private tunnel, not a public port.

## Next

- Fix the PWA Ask endpoint selection: it still hard-codes the browser's localhost, which fails when opened from another device. Add an explicit connection/pairing flow without baking credentials into static JavaScript, then exercise that surface before voice work.
- Voice transcription and model-driven agent orchestration are still separate unbuilt stages; this unit only establishes the API access boundary.
