# Food-first Ask cards, photo previews, and review answers

## Summary

Demo readiness items 1–3 for the food-first 3-minute demo. Ask now searches extracted dishes and menu/sign text and returns structured visit cards. Each card carries the place name with its provenance, dishes with their basis, evidence photo ids, and any open review question. The API serves stripped photo previews and accepts review answers. The PWA Ask panel renders the cards with thumbnails and Yes/No/Name buttons. Before this change, Ask returned "unknown" for "steak restaurant in Tokyo", unnamed visits for "what did I eat in Kyoto", and raw visit-id JSON in the panel. There was also no way to answer any of the 335 open review questions.

## Changes

- `crumbs/ask.py` (AGT v1.1): new dish/menu-text family. Dish names weigh 2, visible text 1, and a whole phrase matched in one photo gets a bonus. Every term must match within a visit, with light plural stemming and CJK runs. City areas now have their own radii (15–60 km) instead of 2 km around the center. "What did I eat in <city>" lists food visits, best-evidenced first. "Have I been to <X>" returns a designed unknown. Place questions return only visits that resolve to that place, falling back to close candidates with an explicit header. Every answer keeps `status/answer/evidence` and adds `results` cards.
- Place provenance, shown on each card: you confirmed > you named it > reconciler candidate labelled "sign text + GPS" or "nearby (GPS)" > unconfirmed text read in the visit's photos. A rejected candidate is never shown as the place.
- `crumbs/review.py`: `open_questions` and `answer_question` (confirm | reject | name | skip). An answer is stored as its own `visit_resolutions` row with created_by='user'. The reconciler's row is never modified, and `reconcile` already leaves user rows and answered questions alone.
- `crumbs/api.py`: `GET /v1/media/<id>/preview` (the stripped preview from the labeler's `ensure_preview`; originals are never served), `GET /v1/review`, and `POST /v1/review/<id>`. The module is no longer described as read-only. Without a token, writes refuse foreign `Origin`s, so another website cannot answer questions through localhost.
- PWA (`spike/map-globe`): Ask cards with thumbnails loaded as blobs with an optional bearer token, a provenance badge, dish chips with basis, and review buttons. The API base and token can be overridden through browser-local `localStorage` (`crumbsApi`, `crumbsToken`), and nothing is baked into the bundle. The panel is widened to 380 px.
- `demo/DEMO.md`: beats 3–4 rewritten food-first around the built cards and review answers; the pipeline table row for Ask/serve updated.

## Validation

- `python3 -m unittest discover -s tests`: 26 passed. New `tests/test_ask_review.py` (7 tests, synthetic store) covers dish search cards, area scope and plurals, text-name cards, the designed unknown, confirm appending a user row while keeping the model row, reject then re-answer replacing only the user row, and name/invalid answers. New API tests cover the review/preview routes on an empty store and refusal of tokenless foreign-origin writes.
- Real-store CLI checks: "steak restaurant in Tokyo" gives 6 cards, "what did I eat in Kyoto" gives 5 food visits with menu-read dishes and sign-read names, "soup dumplings in Taipei" gives 1 visit, and "have I been to Paris?" gives the unknown.
- Surface check: `crumbs serve` ran on a scratch copy of the DB, alongside Vite dev and headless Chromium (Playwright). Three queries rendered cards with all thumbnails loaded and no console errors. Pressing Yes turned a card to "✓ you confirmed" (the first run exposed a detached-node bug, which was fixed and re-run). User rows were written only to the scratch copy; the real store still has 0 user resolutions. Screenshots stayed outside the repo because they show real photos. Both servers were stopped afterwards.
